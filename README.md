# TraitMix — Diverse Minds, Divided Networks?

Reproducible codebase for *Personality Composition, Polarization, and Collective
Intelligence in LLM-Based Social Simulations* (target: EPJ Data Science).

The whole study runs on **one 24 GB consumer GPU**, on public data. Every number in the
paper comes from `results/raw_results.jsonl` through `analysis/`; tables and figures are
generated by script and never typed by hand.

## What is here

**991 analysed simulation runs**, spanning six language models from 3B to 32B parameters
across two families, six contested discussion topics, and a set of ablations that remove
features of the design which could otherwise generate the effects they are used to measure.

| Directory | Contents |
|---|---|
| `src/traitmix/` | the simulation engine, agents, network, metrics |
| `configs/` | one file per experimental condition, grouped by experiment |
| `analysis/` | aggregation and statistics |
| `results/` | run-level records, derived measures, per-round opinion histories |
| `paper/` | generated figures, tables and the supplementary document |

## Reproducing the analysis

No GPU is needed to reproduce every number, figure and table from the released records.

```bash
conda create -n traitmix python=3.12 && conda activate traitmix
pip install -r requirements.txt

python analysis/aggregate_results.py     # statistics from the run-level records
python make_paper_tables.py              # LaTeX tables
python make_paper_figures.py             # results figures
python make_overview_figures.py          # study overview
python make_sixmodel_figure.py           # cross-model response surfaces
python make_topic_figure.py              # six-topic replication
python make_dynamics_figure.py           # opinion dynamics over rounds
python make_society_figures.py           # the society over time
python make_extra_figures.py             # forest plot and association figure
python make_results_ledger.py            # ledger and run accounting
python make_supplementary.py             # supplementary document
python make_supplementary_figures.py
```

`aggregate_results.py` prints its version and the number of standardisation groups on
startup. Collective-performance composites are standardised within model and measurement
regime, so a reported value does not depend on which other experiments are present in the
released data.

**Where every number comes from.** `results/results_ledger.csv` lists each quantity quoted
in the article with the file, column and aggregation that produced it.
`results/run_accounting.csv` maps every condition prefix to its experiment, model and topic
set, and the counts sum to the reported total.

## Reproducing the simulations

Runs need a served model. The study used vLLM on a single RTX 4090.

```bash
vllm serve unsloth/Meta-Llama-3.1-8B-Instruct \
  --served-model-name meta-llama/Llama-3.1-8B-Instruct \
  --max-model-len 4096 --gpu-memory-utilization 0.90

PYTHONPATH=src python -c "
import json, sys; sys.path.insert(0,'src')
from pathlib import Path
from traitmix.runner import run_grid
from traitmix.classifier import make_scorer
M = json.load(open('configs/MANIFEST.json'))
run_grid([Path('configs')/c for c in M['E1']['configs']], M['E1']['seeds'],
         trait_scorer=make_scorer())"
```

`configs/MANIFEST.json` lists every experiment with its conditions and seeds. Completed runs
are recorded as they finish and skipped on restart, so a grid can be interrupted safely.

### Adding a model or an experiment

```bash
python make_model_grid.py --exp e3 --tag mymodel --model org/model-id
python generate_ablations.py            # the measurement-circularity ablations
python generate_topic_extension.py      # the six-topic replication
```

Each generator copies published conditions unchanged apart from the one thing under test,
and verifies that compositions match their source before writing.

## Validity checks

The following are part of the method rather than an appendix, and each is reported in the
article including where it was not passed.

| Check | Script |
|---|---|
| personality induction, per model | `validate_induction_per_model.py`, `recompute_induction.py` |
| neutral filler topic and truncation | `diagnose_confounds.py` |
| perturbation audit | `audit_sign_stability.py` |
| probe and recommender ablations | `generate_ablations.py` |
| exposure to the estimation tasks | `measure_ci_exposure.py` |
| counts behind the segregation rates | `measure_denominators.py` |
| silent-failure detection | `scan_dead_runs.py` |

`scan_dead_runs.py` is worth running after any new batch. It detects runs that completed
without the model actually responding, which produce complete and plausible-looking records.

## Notes

Runs from one model were discarded because the inference server returned errors during them
that could not be ruled out as having affected the generated data; those records are kept
separately in `results/quarantined_excluded_runs.jsonl` and are excluded from all analysis.
Two further models completed but did not pass induction validation and are reported in the
supplementary material rather than the main results.

The `results/timeseries/` directory holds per-round opinion records, needed to regenerate two
figures. It is the bulk of the repository.
